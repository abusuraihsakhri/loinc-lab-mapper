# LOINC Lab Mapper

A small, **curated laboratory terminology matcher** for local test names and candidate LOINC codes. Includes a dependency-free Python lookup engine, CSV processing, a browser-based Python interface, and a separate demonstration FastAPI audit console.

**Important:** This is a terminology review utility, not a validated clinical coding system. Its catalog is incomplete, fuzzy scores are not probabilities, and a match does **not** establish agreement on specimen, property, time, method, or units. Verify proposed codes against the [official LOINC catalog](https://loinc.org/) before use.

## Browser application

The static application in [docs/](docs/) runs the existing Python mapper with [Pyodide](https://pyodide.org/) in a modern WebAssembly-capable browser. It supports single lookups and CSV upload/export.

GitHub Pages deployment is configured in [the Pages workflow](.github/workflows/pages.yml). Its public URL should be published here **only after a successful live-site check**.

Browser input and CSV content are processed locally; the app does not intentionally transmit them to a backend. **First use requires internet** to download the pinned Pyodide runtime from jsDelivr. Do not use patient-identifiable files.

## Python installation

Python 3.10+:

~~~bash
git clone https://github.com/abusuraihsakhri/loinc-lab-mapper.git
cd loinc-lab-mapper
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
~~~

On Windows, activate with .venv\Scripts\activate.

### Lookup and CSV mapping

~~~bash
loinc-lookup single creatinine
loinc-lookup single "free t4" --max-results 3
loinc-lookup batch --input sample.csv --output results.csv
~~~

Equivalent source commands are python loinc_mapper.py single creatinine and python loinc_mapper.py batch --input sample.csv --output results.csv.

Input must be UTF-8 CSV with a header. The mapper prefers a column named query, test, lab, or name (case-insensitive), otherwise the first column. Export appends top_hit and lookup_score. The existing loinc-mapper console entrypoint instead launches the separate audit demonstration CLI.

### Local demonstration console and API

~~~bash
loinc-mapper audit --task-id TEST-001 --primary 28.5 --secondary 14.2
loinc-mapper verify-audit
loinc-mapper serve --host 127.0.0.1 --port 8000
~~~

Open http://127.0.0.1:8000/console for the local HTML console or http://127.0.0.1:8000/docs for autogenerated FastAPI documentation. Endpoints include GET /health, GET /metrics, POST /api/audit, POST /api/chat, and GET /api/audit/logs.

**Audit worker thresholds are arbitrary demonstration settings**, not CAP, CLSI, or ISO reference intervals or clinical safety rules. Chat providers currently return mock responses even when alternate provider names are selected. The API has no built-in authentication: **keep it on a trusted local interface and never expose it as a public clinical service**.

### Docker

Supply a new secret via your environment instead of embedding one in Compose:

~~~bash
export AUDIT_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
docker compose up --build
~~~

Compose binds the host port to 127.0.0.1:8000. Refer to [.env.example](.env.example) for variable names; do not commit populated .env files.

## How matching works

The bundled LOINC_DATABASE in [loinc_mapper.py](loinc_mapper.py) contains a limited set of test labels and aliases. Matches are ranked by exact alias/code, substring/token overlap, and Levenshtein similarity. Returned scores are **heuristic ranking values, not likelihoods or confidence intervals**.

Several historically mismatched bundled identities have been corrected (including CRP/hs-CRP, ESR, TSH, thyroid hormones, BUN, and blood-gas analytes). The code list is *not* a complete LOINC distribution or a substitute for authenticated terminology mapping. Cross-check the official code specification before deploying in LIS/EHR pipelines.

## Privacy and security limitations

- The standalone browser mapper processes files locally after runtime loading; runtime assets download from a third-party CDN.
- The API's audit log is in-memory and HMAC-chained. Verification detects modifications to retained entries, but logs **do not survive restarts** and are not an externally durable evidentiary record.
- Set AUDIT_SECRET_KEY for a deployment; otherwise, the process creates an ephemeral secret. Do not reuse a previously published secret.
- The PHI guard is a **limited regular-expression filter**, not full de-identification and not a HIPAA compliance guarantee. Avoid entering protected health information into either interface.
- The local demo API is unauthenticated and is not suitable for public internet exposure.

## Tests and development

~~~bash
python -m pip install -e ".[dev]"
python -m pip check
python -m compileall -q agents loinc_mapper.py cli.py enrichment.py simulator.py
pytest -v
node --check docs/app.js
~~~

CI runs the Python test matrix on 3.10, 3.11, and 3.12, checks JavaScript syntax, and smoke-tests installed CLI commands. The separate Pages workflow packages the browser HTML, JavaScript, and Python source without a backend.

## Technology and compatibility

Python standard library, FastAPI/Pydantic/Uvicorn for the local API, and Pyodide/WebAssembly for browser execution. A current JavaScript- and WebAssembly-capable browser with internet access for initial runtime loading is required. No model inference, server-side Python, or private API keys are used for the browser mapper.
